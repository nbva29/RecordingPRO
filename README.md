# ЗаписьПро

**ЗаписьПро** — веб-приложение для онлайн-записи клиентов к специалистам организаций малого бизнеса.

Платформа позволяет клиентам находить организации, выбирать услуги и записываться на удобное время. Администраторы могут управлять услугами, расписанием специалистов и бронированиями.

## Технологический стек

**Frontend:**

- React
- TypeScript

**Backend:**

- Python
- FastAPI
- MySQL

**Инфраструктура:**

- Git и GitHub
- Docker и Docker Compose

## Локальный запуск

### Frontend

Требуется установленный Node.js и npm.

```bash
cd frontend
npm install
npm run dev
```

Адрес приложения: http://localhost:5173

### Backend

Требуется установленный Python.

Перейдите в папку backend:

```bash
cd backend
```

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте окружение на Windows:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

При первой настройке скопируйте `backend/.env.example` в `backend/.env`
и укажите данные подключения к своей базе MySQL. Файл `.env` исключён из Git.
Для `JWT_SECRET_KEY` сгенерируйте собственный секрет командой
`python -c "import secrets; print(secrets.token_urlsafe(32))"`
и запишите результат в `.env`. По умолчанию токен действует 30 минут
(`ACCESS_TOKEN_EXPIRE_MINUTES=30`).
Из папки `backend` примените миграции:

```bash
python -m alembic upgrade head
```

Начальная миграция создаёт таблицы `users`, `roles` и добавляет роли
`client` (клиент) и `admin` (администратор).

Запустите сервер:

```bash
python -m uvicorn app.main:app --reload
```

Адрес API: http://localhost:8000

Документация Swagger: http://localhost:8000/docs

Регистрация клиента: `POST /api/auth/register`. Пример JSON-запроса:

```json
{
  "email": "client@example.com",
  "password": "ExamplePassword123!"
}
```

Успешный ответ: `201 Created`, повторный email: `409 Conflict`,
некорректные данные: `422 Unprocessable Entity`.
Регистрация создаёт клиента; пароль и его хеш в ответ не включаются.

Вход: `POST /api/auth/login` с JSON-полями `email` и `password`.
Успешный ответ `200 OK` содержит `access_token`, `token_type: "bearer"`
и `expires_in` (срок действия в секундах). Неверный email или пароль
возвращает `401 Unauthorized`.

Текущий пользователь: `GET /api/auth/me` с заголовком
`Authorization: Bearer <access_token>`. Отсутствующий, недействительный
или просроченный токен возвращает `401 Unauthorized`.
Для проверки в Swagger выполните вход, скопируйте `access_token`, нажмите
**Authorize** и вставьте только токен. Затем выполните `GET /api/auth/me`.

### Профиль и смена пароля

Оба запроса требуют `Authorization: Bearer <access_token>` и работают
с текущим пользователем.

Изменение профиля: `PATCH /api/auth/me`. Пример JSON-запроса:

```json
{
  "name": "Денис",
  "phone": "+7 999 000-00-00"
}
```

Разрешено менять только `name` (до 100 символов) и `phone` (до 32 символов).
Пробелы по краям удаляются; пустые строки отклоняются. Формат телефона
не ограничен. Переданное значение `null` очищает поле, пропущенные поля
сохраняют прежние значения. Пустой объект ничего не меняет.
Успешный ответ `200 OK` содержит профиль в том же формате, что и
`GET /api/auth/me`. Другие поля, включая `email`, `role_id` и пароль,
отклоняются с `422`.

Смена пароля: `POST /api/auth/change-password`. Пример JSON-запроса:

```json
{
  "current_password": "ExamplePassword123!",
  "new_password": "NewExamplePassword456!"
}
```

Текущий пароль проверяется перед изменением; новый должен содержать
от 8 до 128 символов и сохраняется только в виде хеша Argon2id.
Успешный ответ — `204 No Content` без тела. Неверный текущий пароль
возвращает `400 Bad Request`, некорректные поля — `422`.
Пароли и их хеши в ответы не включаются. После смены пароля вход работает
с новым паролем; ранее выданные JWT действуют до окончания своего срока.
Без действительного токена оба запроса возвращают `401 Unauthorized`.

### Восстановление пароля

Примените миграции командой `python -m alembic upgrade head`
из папки `backend`. Миграция `0006` заменяет восстановление по ссылке
на шестизначный код из письма и добавляет ограничение попыток.
Ранее отправленные ссылки после обновления не действуют.

Для отправки через Gmail включите двухэтапную аутентификацию и создайте
[пароль приложения Google](https://support.google.com/accounts/answer/185833?hl=ru).
Добавьте в локальный `backend/.env` следующие настройки, заменив заглушки:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=your-address@gmail.com
SMTP_PASSWORD="YOUR_APP_PASSWORD"
SMTP_FROM=your-address@gmail.com
PASSWORD_RESET_EXPIRE_MINUTES=15
```

В `SMTP_PASSWORD` укажите пароль приложения без пробелов, а в `SMTP_FROM` —
тот же адрес, что и в `SMTP_USER`. Пароль хранится только в локальном `.env`.
После изменения настроек перезапустите backend.
Если в локальном `.env` осталась строка `PASSWORD_RESET_URL`, удалите её:
восстановлению по коду адрес страницы больше не нужен.
Используется [SMTP Gmail](https://developers.google.com/workspace/gmail/imap/imap-smtp):
порт `465` с TLS; при указании `587` соединение защищается через STARTTLS.

Запрос письма: `POST /api/auth/forgot-password`, без авторизации:

```json
{
  "email": "client@example.com"
}
```

При обычной работе ответ `200 OK` одинаков для зарегистрированного
и неизвестного email:

```json
{
  "detail": "Если email зарегистрирован, на него отправлено письмо восстановления"
}
```

Письмо отправляется только зарегистрированному пользователю.
Письмо содержит код из 6 цифр, а не ссылку. Код не возвращается в API.
По умолчанию он действует 15 минут. Повторно запросить письмо можно
через 60 секунд; ранний повторный запрос возвращает `429`.
Успешная отправка нового кода отменяет предыдущий. Если почта не настроена
или отправка завершилась ошибкой, API возвращает `503`.

Пользователь вводит email, код и новый пароль в форме восстановления.
Форму и её подключение реализует frontend в задачах S2/S4.
До её появления подтверждение можно проверить через Swagger.

Подтверждение: `POST /api/auth/reset-password`, без авторизации:

```json
{
  "email": "client@example.com",
  "code": "012345",
  "new_password": "NewExamplePassword456!"
}
```

Поле `code` передаётся строкой из 6 цифр, чтобы сохранить ведущие нули.
Email приводится к нижнему регистру. Новый пароль — от 8 до 128 символов.
Код привязан к конкретному пользователю; в БД хранится только HMAC-хеш
кода с использованием серверного секрета.
Успешный ответ — `204 No Content`. Код погашается в той же транзакции,
которая меняет хеш пароля. Блокировка строки пользователя защищает
от одновременного повторного использования и потери счётчика попыток.
После 5 неверных попыток код отменяется — нужно запросить новый.
Недействительный, использованный, заблокированный или просроченный код
возвращает `400`; некорректные поля запроса — `422` и не расходуют попытки.
После восстановления вход работает с новым паролем, ранее выданные JWT
действуют до окончания своего срока. Обычная смена пароля через
`/api/auth/change-password` также отменяет ранее запрошенный код.

### Организации

Создавать и редактировать организации может только пользователь с ролью
`admin`. Токен передаётся в заголовке `Authorization: Bearer <access_token>`.

- `POST /api/organizations` — создать организацию;
- `GET /api/organizations/{id}` — получить организацию (доступно без авторизации);
- `PATCH /api/organizations/{id}` — изменить переданные поля.

Пример создания:

```json
{
  "name": "Студия красоты «Лайм»",
  "description": "Уютная студия красоты",
  "address": "Томск, ул. Тверская, 12",
  "city": "Томск",
  "phone": "+7 999 000-00-00"
}
```

Обязательные поля — `name`, `address`, `city`; `description` и `phone`
необязательны. Пустые `name`/`address`/`city` и неизвестные поля отклоняются
с `422`. Без токена API отвечает `401`, клиенту без роли `admin` — `403`,
для несуществующей организации — `404`.

В `PATCH` можно очистить необязательные поля, передав `null`
(`{"description": null, "phone": null}`). Явный `null` в `name`, `address`
или `city` возвращает `422`.

### Категории и услуги

Категория объединяет услуги одной организации, цена хранится в целых рублях.
Создание, изменение и удаление доступны только администратору, списки —
без авторизации.

- `GET /api/organizations/{id}/categories` — категории организации;
- `GET /api/categories/{id}` — получить категорию;
- `POST /api/organizations/{id}/categories` — создать категорию;
- `PATCH /api/categories/{id}` — переименовать категорию;
- `DELETE /api/categories/{id}` — удалить категорию без услуг;
- `GET /api/organizations/{id}/services` — услуги организации;
- `GET /api/services/{id}` — получить услугу;
- `POST /api/organizations/{id}/services` — добавить услугу;
- `PATCH /api/services/{id}` — изменить услугу и цену;
- `DELETE /api/services/{id}` — удалить услугу.

Пример услуги (`duration` — длительность в минутах):

```json
{
  "category_id": 1,
  "name": "Маникюр с покрытием",
  "description": "Гель-лак",
  "price": 2000,
  "duration": 60
}
```

Названия категорий уникальны в пределах организации (`409` при повторе).
Категорию, в которой ещё есть услуги, удалить нельзя (`409`). Неизвестные
поля, отрицательная цена, нулевая длительность и `null` в обязательных полях
отклоняются с `422`. В `PATCH` явный `null` очищает `description`; `price >= 0`
дополнительно проверяется ограничением в БД.

### Каталог организаций

`GET /api/organizations` — список организаций с категориями и услугами.
Доступен без авторизации. Необязательные параметры запроса:

- `search` — поиск по названию организации;
- `city` — фильтр по городу;
- `category` — фильтр по названию категории услуг.

Пример: `/api/organizations?search=Лайм&city=Томск&category=Маникюр`.
Поиск по названию и фильтр по городу ищут подстроку без учёта регистра;
символы `%` и `_` воспринимаются как обычный текст.
Ответ — массив организаций; у каждой есть `categories`, а в них `services`:

```json
[
  {
    "id": 1,
    "name": "Студия красоты «Лайм»",
    "description": "Уютная студия красоты",
    "address": "Томск, ул. Тверская, 12",
    "city": "Томск",
    "phone": null,
    "categories": [
      {
        "id": 1,
        "name": "Маникюр",
        "services": [
          {
            "id": 1,
            "category_id": 1,
            "name": "Маникюр с покрытием",
            "description": null,
            "price": 2000
          }
        ]
      }
    ]
  }
]
```

Карточка организации: `GET /api/organizations/{id}` возвращает один объект
в том же формате.
